jawaban soal C : ada 2 strategi yaitu vertical scale dan horizontal scale. saya akan menjelaskan dari vertical scale. vertical scale adalah cara yang paling cepat dilakuakan yaitu menaikkan spesifik hardware server. jadi server aplikasi di naikkan dari segi CPU, RAM, dan penyimpanan ke SSD. tapi bottleneck yang akan terjadi adalah ketika server terus membengkak harus selalu upgrade sehingga memakan biaya tinggi, dan ketika pengguna sepi, upgrade yang dilakukan sia-sia hanya menambahkan cost saja.



lalu Horizontal scale, yaitu salah satunya bisa menggunakan load balancing, aplikasi di deploy di beberapa server (instance) kecil kecil, lalu load balancing bisa mengatur arusnya agar dapat dibagi merata. bisa juga menggunakan bawaan dari fitur cloud misal saja gcp, ketika menggunakan cloud run, kita bisa mengaktifkan fitur autoscale jadi tidak perlu setup scale manual. lalu bisa menggunakan caching data, anggap saja session dari user di simpan di redis (inmemory database) sehingga request yang berhubungan dengan session/token dilakukan oleh redis. bisa juga data yang jarang berubah ditambahkan ke caching seperti hasil query revenue harian, data historis dll. kemudian bisa juga mulai menerapkan pada backend dengan aristek CQRS (Command Query Responsibility Segregation) jadi memisahkan servis untuk read dan write pada db yang terpisah. permasalahannya disini adalah skill developer harus sudah tinggi dan ada beberapa setup yang tergolong susah untuk menerapkannya jika tidak pernah menggunakannya. tapi sebelum itu, ada baiknya di check dulu dengan aplikasi observable log seperti open telemetry dan grafana, agar dapat di deteksi lebih akurat service mana yang butuh di scale dan bisa menerapkan rate limit untuk menghindari adanya bot yang mencoba membuat lonjakan trafik secara anomali.
